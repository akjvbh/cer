# 项目定位与技术栈

## 这个项目是什么

一个在 Windows 本机运行的「办公文档工具箱」。后端 FastAPI，前端原生 HTML/CSS/JS，双击 `start.bat` 启动，浏览器打开 `http://127.0.0.1:8000` 就能用。

核心卖点：**文件只在本机处理**。除「文献翻译」会调用用户自己配置的大模型接口外，任何文件内容都不许发往第三方服务器，也不许用任何在线转换服务。

## 技术栈（硬性，不得替换）

- 后端：Python 3.10+、FastAPI、uvicorn、python-multipart、python-dotenv
- 前端：原生 HTML + CSS + JS。**禁止** React / Vue / Tailwind / 任何 npm 依赖 / 任何构建步骤（项目里不允许出现 `package.json`、`node_modules`、`vite`）
- PDF 读写：PyMuPDF（`import fitz`）；HTML 排版成 PDF 也用它的 `insert_htmlbox`，必要时加 reportlab
- PDF → Word：pdf2docx
- Word / Excel / PPT → PDF：pywin32 调本机 Microsoft Office，属于**可选能力**，用不了时必须明确报错或降级
- 图片与扫描件：Pillow、opencv-python-headless
- Word 生成：python-docx；Excel 生成：openpyxl；读旧版 `.xls`：xlrd；Markdown：markdown；docx → html：mammoth
- 翻译：任意 OpenAI 兼容的 `/chat/completions` HTTP 接口（`requests` 和 `httpx` 只选一个，不要都装）

## 允许新增的文件与依赖（白名单，超出先问我）

`office_worker.py`、`assets/fonts/`（中文字体子集）、`xlrd`、`reportlab`、`mammoth`。

不做的事：数据库、Redis / Celery、前端框架、GUI 版 OpenCV、pytesseract（本版不做 OCR）。

## 本版范围（需求确认表 v0.2 已锁定，不要擅自扩大）

- **转换**：`docx`→pdf/txt/html/md｜`doc`→pdf/docx（需 Word）｜`xlsx`→pdf/csv｜`xls`→xlsx/csv｜`pptx`→pdf/png、`ppt`→pdf（需 PowerPoint）｜`pdf`→docx/txt/png/jpg｜`csv`→xlsx｜`md`→html/pdf｜`txt`→docx/pdf｜图片互转｜图片→pdf/docx
- **压缩**：只做 **PDF + 图片**，四档 `80/60/40/20`。docx/xlsx/pptx 不压缩，界面提示不支持
- **PDF 工具**：合并 / 删页 / 旋转 / 重排 / 复制页 / 逐页导出 JPG（每张 ≤300KB）/ 页面预览
- **AI 增强**：文献翻译（「保留版式 PDF」**只接受 PDF 输入**）、扫描件增强
- **明确不做**：OCR 文字识别、加密 PDF 解密、独立的 PDF 标注/批注工具（标注坐标规则只服务于翻译覆盖层）

## 交付标准（每个阶段结束时都必须成立）

1. 双击 `start.bat`，或在项目根目录执行 `.\.venv\Scripts\python.exe main.py`，10 秒内启动成功，不依赖任何云服务。
2. 没装 Microsoft Office 的机器上：`docx→pdf` 走内置排版引擎并带 note；`.doc/.ppt/.pptx` 明确报错并提示「需要本机 Office / PowerPoint」，**不允许假装成功**，也不允许直接 500。
3. 每个接口都有输入校验（扩展名白名单 + 文件头 + 大小上限），错误统一返回 `{"error": "中文可读信息"}`。
4. 不引入数据库，不引入 Redis / Celery 之类外部进程。任务状态放进程内字典，服务重启后清空是可接受的。
5. 每个功能都能用 `curl.exe` 单独验证，不依赖前端。

## 界面基调

- 中文界面，术语用办公场景的说法（「文献翻译」而不是「文本翻译」）
- 单页，左侧功能导航，中间操作区，右侧结果卡片
- 深色 / 浅色 / 跟随系统三态主题，存 `localStorage`
- 空状态、加载中、失败三种状态都要有明确文案，不能只转圈
- 响应式断点 900px

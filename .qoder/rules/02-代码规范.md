# 代码规范

## Python

- 函数签名写类型注解：`def convert(src: Path, dst_dir: Path, target: str) -> tuple[Path, str]:`
- 每个转换 handler 只做一件事，函数不超过 80 行；超过就拆成多个私有函数
- **禁止** `except: pass`、`except Exception: pass`。要么记录日志并带上原因返回给前端，要么往上抛，由路由层统一转成 `{"error": ...}`
- 上传文件一律改名成 `uuid4().hex + 原扩展名` 落盘，不要用用户给的原始文件名拼路径
- 临时文件写完就删，用 `try/finally`；`uploads/` 和 `outputs/` 里的中间文件在任务结束后清理（下载需要保留的除外，保留 1 小时后后台清理）
- 日志用 `logging`，不要用 print；格式 `%(asctime)s %(levelname)s %(message)s`
- 超时、大小、质量等常量放模块顶部，不要散落在函数体里
- 第三方库缺失时，导入放在函数内部并用 `try: import ... except ImportError:` 给出明确提示（例如没装 pywin32 就降级，不要整个服务起不来）

## 前端（原生 JS）

- 不引入第三方库、CDN 字体、图标库；图标用 emoji 或内联 SVG
- 一个页面：`index.html` 只写结构，样式全在 `app.css`，逻辑全在 `app.js`，不要内联 `<style>` 和大段 `<script>`
- 事件监听用事件委托挂在容器上，不要给每个文件卡片单独绑定
- **禁止**把用户提供的文件名拼接进 `innerHTML`（XSS）。一律 `textContent`，或在插入前做 `escapeHtml()`
- 上传用 `FormData`；需要上传进度时用 `XMLHttpRequest`，不需要就别用
- 轮询任务进度用 `setTimeout` 递归调用，任务结束后必须 `clearTimeout`；不要用永不停止的 `setInterval`
- 所有 `fetch` 都要 `try/catch`，失败给用户一句中文提示，而不是只 `console.error`
- 全局状态集中在一个 `state` 对象里（已选文件、当前标签、当前任务），不要在 `DOM.dataset` 里藏业务状态

## 通用

- 标识符用英文，注释与用户可见文案用中文
- 不写「将来可能用到」的抽象；不为没实现的功能预留空壳
- 改一个功能时不要顺手重构别的文件；确有必要的先单独说明理由
- 文件编码统一 UTF-8，换行 LF，`.gitattributes` 里对 `*.bat` 用 CRLF
- 不提交 `uploads/`、`outputs/`、`.venv/`、`__pycache__/`、`.env`

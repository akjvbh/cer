# 用 Qoder 从零重做文档转换器 · 提示词包

一套可以直接粘贴使用的提示词，目标是在 Qoder 里从空目录做出一个**能跑、能演示**的本地办公文档转换器（FastAPI + 原生 JS）。

思路只有一条：**规则文件管住 AI 的行为边界，规划提示词一次讲清需求，分阶段提示词让它一段一段交付能跑的代码**。把几千行需求一口气丢给 AI，出来的通常是一堆跑不起来的文件。

> **本包版本 v0.2**：已按 [需求确认表 v0.2](../deliverables/决策纪要.md) 锁定范围——旋转是最终角度（覆盖）、批量统一走 `task_id`、压缩只做 PDF + 图片、不做 OCR 和独立标注工具、健康检查不启动 Word。规则与阶段提示词已同步，直接粘贴即可，不要再按旧口径补充。

---

## 一、准备

1. 装好 Qoder IDE，模型选最强的档。
2. 新建一个空目录，例如 `D:\123456\doc-converter-qoder`，在 Qoder 里打开它。
3. 本机装 Python 3.10+。有 Microsoft Office 更好（没有也能跑完，`docx→pdf` 会走内置排版引擎）。
4. 把现有项目的两篇真实文件复制进新项目的 `samples\` 当测试素材：

```powershell
New-Item -ItemType Directory -Force D:\123456\doc-converter-qoder\samples | Out-Null
Copy-Item "D:\123456\office-converter\source_docs\*" D:\123456\doc-converter-qoder\samples\
```

## 二、按顺序使用

| 步骤 | 做什么 | 用哪个文件 | 预计 |
|---|---|---|---|
| 0 | 把规则放进新项目的 `.qoder\rules\` | `rules\*.md`（5 个） | 5 分钟 |
| 1 | 让它先出方案，**不写代码** | `01-plan-prompt.md` | 5 分钟 + 你评审 10 分钟 |

| 4 | 压缩 + PDF 工具（合并 / 页面操作 / 导出） | `04-stage3-压缩与PDF工具.md` | 60 分钟 |
| 5 | AI 增强（文献翻译 / 扫描件增强） | `05-stage4-AI增强.md` | 60–90 分钟 |

## 三、规则文件怎么放

Qoder 的项目规则放在 `.qoder/rules/`，**一个文件一条规则**，文件名就是规则名。复制过去：

```powershell
cd D:\123456\doc-converter-qoder
New-Item -ItemType Directory -Force .qoder\rules | Out-Null
Copy-Item "D:\123456\office-converter\qoder-prompts\rules\*.md" .qoder\rules\
```

然后在 Qoder 里 `Ctrl+Shift+,` → Rules，给每个文件设置生效方式（也可以在 Rules 面板里新建，再把内容粘进去）：

| 规则文件 | 生效方式 | 管什么 |
|---|---|---|
| `01-项目定位与技术栈.md` | Always Apply | 技术选型、目录结构、交付标准 |
| `02-代码规范.md` | Specific Files：`*.py, static/*.js, static/*.css` | 命名、异常处理、前端不用框架 |
| `03-API-契约.md` | Always Apply | 接口表、页码与坐标语义 |
| `04-开发流程.md` | Always Apply | 先读再改、不伪造、小步验证 |
| `05-已知坑.md` | Always Apply | Office COM、上传安全、性能 |

几点说明：

- Qoder 的规则是**自然语言**，不支持图片和链接；所有规则累计上限 10 万字符（部分版本单文件上限 1 万），这套约 1 万字符，够用。
- 如果你的 Qoder 版本支持 `AGENTS.md`，把 `01 + 03 + 04 + 05` 拼成一份 `AGENTS.md` 放根目录也行（规则内容优先于 `AGENTS.md`）。
- 规则不是越多越好。**跑起来之后就别再往里堆**，否则会把上下文挤掉。

## 四、每一阶段的「完成标志」

不要听它说「已完成」，看这四个条件同时成立：

1. `.\.venv\Scripts\python.exe main.py` 能启动，浏览器能打开界面
2. 本阶段的验收命令能跑出预期结果（每个阶段文件末尾都写了）
3. `python tests/smoke.py` 全绿
4. 有一个 git 提交

任何一条不满足，就用 `07-纠偏提示词.md` 里对应的场景，别继续往下推。

## 五、比赛加分项（按性价比排序）

1. **每个阶段可演示**：中途被叫停也能上台讲，这比功能多更稳。
2. **降级路径**：Office 不可用自动换内置排版引擎、翻译未配置时界面明确提示。现场环境不可控，降级就是你的安全垫。
3. **过程可追溯**：`git log` 每阶段一个提交 + `.qoder/rules` + 规划输出截图。要求"用 Qoder"的比赛，这就是证据。
4. **真实痛点开场**：合同不敢传云端、扫描件要删页改字、英文文献一段段复制。别用"我做一个转换器"开场。
5. **一个技术细节讲透**：PDF 页码语义（1-based、白名单、复制页、旋转是最终角度不是叠加）最能体现"这不是套壳"，比罗列功能有说服力。
6. **数据说话**：压缩率、翻译 10 页的耗时、50 页 PDF 转 JPG 的秒数，提前测好写在 README 里。

## 六、已知坑（提前避开，比事后修便宜）

- **不要让它一次写 5 个模块**。它会在第 3 个模块开始「假设」前两个模块的函数名。
- **不要让它自己决定页码语义**。混用 0-based / 1-based、增量旋转 / 绝对旋转，是这类项目最经典且最难发现的 bug。
- **不要让它装前端框架**。你说"原生 JS"，它可能顺手给你一个 React 版；规则里写死禁止，出现过一次就重置对话。
- **别信"已测试"**。要求贴命令和输出（`07` 场景 F）。
- **中文 PDF 必须嵌字体**，否则翻译结果全是方框。
- **Office COM 一定要串行 + 超时 + 杀进程**，否则演示时会挂出一个看不见的 Word 窗口。
- **每阶段提交一次**。它改坏了，`git checkout` 比跟它讲道理快。

## 八、范围基线（v0.2，三张表锁定）

来源：[需求确认表-v0.2-已填写.xlsx](../deliverables/需求确认表-v0.2-已填写.xlsx)，逐条理由见 [决策纪要](../deliverables/决策纪要.md)。开发中如果和下面的说法冲突，以这一节为准。

| 主题 | 结论 |
|---|---|
| 旋转 | 请求角度 = **最终角度**，覆盖原 rotation；原文件自带旋转要回传给前端做初始显示 |
| 页序 | `page_order` 非空才是白名单（可重复 = 复制页）；空数组 = 未传，`delete_pages` 生效 |
| 标注 | 本版没有 PDF 标注接口；坐标规则只用于翻译覆盖层（左上角原点、PDF 点、页码 1-based） |
| 压缩 | 只做 **PDF + 图片**；四档 80/60/40/20；提交前弹「丢文字层」确认框 |
| JPG 导出 | 每张 ≤300KB 是硬指标，降到 72 DPI + q50 仍超则该文件失败 |
| 批量 | 只有一套任务模型：`task_id` → `/api/tasks/{id}` → `/api/download/{id}`（ZIP）；最多 200 个文件 |
| 混合文件夹 | 前端按源格式分组，每组各自 target，分组并行提交 |
| Office | 健康检查用注册表/文件探测，不启动 Word；无 Office 时 `docx→pdf` 走兜底并带 note，`.doc/.ppt/.pptx` 明确报错 |
| 翻译 | `layout` 只接受 PDF；分块 ≤2000 字符、3 线程；任一块失败则整体失败，不产半成品；字体用 Noto Sans SC 子集 |
| 其它 | 加密 PDF 明确报错；GIF/TIFF 只取第一帧；TXT/CSV 用 UTF-8 BOM；多 sheet 导 CSV 打 ZIP；不做 OCR |

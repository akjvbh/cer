# 我如何使用 Qoder 完成文档工坊

本文只记录实际发生过的做法和可核对的文件，不补写没有发生的案例。

## 1. 工作方式

流程是固定的四步：

1. **先定规则**：把项目定位、技术栈、API 契约、代码规范、已知坑写进规则文件，明确哪些事不许做。
2. **再分阶段**：按「骨架 → 格式矩阵与批量 → 压缩与 PDF → AI 增强 → 打磨交付」拆成五个阶段，每个阶段有独立提示词和验收标准。
3. **每阶段真实验证**：用 `tests/smoke.py`、curl 和浏览器实际操作验证，不靠「应该能跑」。
4. **每阶段提交**：一个阶段一个 commit，阶段 5 完成后打 `v1.0-demo` 标签。

## 2. 规则文件清单

规则原文同时保留在 `.qoder/rules/` 和 `docs/rules/`，两处内容一致。

| 文件 | 解决什么问题 |
| --- | --- |
| `01-项目定位与技术栈.md` | 锁定「文件只在本机处理」、Python/FastAPI + 原生前端、禁止 npm/数据库/Redis，明确本版范围 |
| `02-代码规范.md` | 类型注解、函数长度、禁止吞异常、UUID 落盘、临时文件清理、日志规范、前端 XSS 与事件委托 |
| `03-API-契约.md` | 接口清单、异步任务模型、1-based 原页码、旋转最终角度、`page_order` 白名单与复制语义、错误码 |
| `04-开发流程.md` | 先读再改、小步验证、失败贴原文、不伪造测试结果、每阶段提交 |
| `05-已知坑.md` | Office COM 串行/超时/清理、上传校验、加密 PDF、中文编码、PDF 压缩丢文字层、600px 布局等 |

## 4. 三个真实的纠偏案例

### 案例一：`start.bat` 在中文提示后出现 `'g' is not recognized`

- **背景提示词**：阶段 5 要求「端口被占用时自动换端口并在窗口里显示新地址」「加启动日志 `_start_log.txt`」，提示词文件为 `docs/prompts/06-stage5-打磨与交付.md`。
- **实际观察**：功能已经能换到 8001，但控制台在中文提示后出现 `'g' is not recognized`，日志里缺少最后一条地址记录。
- **怎么纠偏**：没有继续在中文行上试错。先用多个最小 batch 文件隔离，确认是 cmd 在 UTF-8 代码页下解析「中文 + 全角标点 + 后续 `call`」时把字节当成了命令。然后把启动流程改成无括号的 `goto` 结构，控制台中文提示保留，写入 `_start_log.txt` 的诊断信息改为 ASCII。
- **结果**：8000 被占用时实际启动在 8001，控制台无解析错误，日志包含 `workdir`、`port 8000 busy, using 8001`、`listening http://127.0.0.1:8001`。

### 案例二：阶段 5 要求撤销「复制页」，但前端没有复制功能

- **背景提示词**：阶段 5 要求撤销栈覆盖「删除、旋转、排序、复制页」四类操作，最多 50 步。
- **实际观察**：页面操作只有删除、旋转、重排，没有「复制选中」，撤销自然也无从覆盖。
- **怎么纠偏**：没有把需求解释成「复制不需要」，而是在工具栏补了「复制选中」，把复制实现为在 `order` 中重复原页码；复制和删除、旋转、重排共用同一个快照栈，超过 50 步丢弃最旧快照。
- **结果**：浏览器实测复制第 1 页后顺序为 `[1,1,2,3]`，`Ctrl+Z` 恢复为 `[1,2,3]`，`Ctrl+Shift+Z` 再恢复为 `[1,1,2,3]`；连续 60 次旋转后历史保留 50 步。

### 案例三：复制页后再删除，导出把被删页带回来

- **背景提示词**：`docs/prompts/07-纠偏提示词.md` 的场景 B 要求「写最小复现、定位期望值与实际值、只改这一处、保留回归证据」。
- **实际观察**：3 页 PDF 复制第 1 页后勾选删除，结果卡显示「删除 1 页；按新顺序保留 3 页，结果共 3 页」，第 1 页复活的。
- **怎么纠偏**：用浏览器脚本复现并打印 `order`、`deleted` 和结果卡原文。根因是删除选中页只移除了第一个匹配项，而导出又无条件把含副本的 `order` 作为白名单提交，后端按契约忽略 `delete_pages`。修复为：删除选中页移除该页所有副本；单页删除按实际位置删除；导出前过滤已删除页，并只在真正重排/复制时提交 `page_order`。
- **结果**：同一操作导出 2 页，下载后用 PyMuPDF 复核文本为 `['B','C']`；撤销/重做仍正常。复现是浏览器脚本，没有单独落 `tests/_repro.py`，回归证据是导出文件页数与文本检查。

## 5. 哪些是人工决定，哪些是 AI 生成

**项目方提供 / 决定：**

- 需求确认表与 v0.2 范围锁定（`docs/prompts/需求确认表*.xlsx`）。
- 技术栈与硬约束：本机处理、原生前端、不用数据库/Redis、Office 可选。
- 五个阶段的验收标准和纠偏要求（`docs/prompts/02`–`08`）。
- 比赛要求、演示取舍和最终是否提交。

**AI 生成并经实际命令验证：**

- 后端、前端、测试脚本的实现与修改。
- `README.md`、`CHANGELOG.md`、`LICENSE`、`.env.example` 的初稿。
- 本文、`docs/DEMO.md`、`docs/QA.md` 的初稿；演示脚本和问答需要项目方按现场设备、是否配置翻译 key、Office 稳定性再删改。

**没有做的：**

- 没有把演示脚本说成已经现场彩排过；它只是基于已经跑通的功能写的脚本。
- 没有为「SaaS 改造」「云端部署」写未实现的代码；这两项只作为答辩边界说明。
